# 3D 视觉的边界：等距投影与层次深度，不做交互式旋转

看板要求「3D 显示」。三种读法差别很大：CSS 层次深度（透视、倾斜、分层投影）、SVG 等距伪 3D（柱体画成顶面/侧面/正面三个纯色块）、WebGL 真 3D。

决定：前两种都做，第三种不做。

**实际落地只有一处用了等距投影**：`_charts.js` 的 `isoBars`，画「今日流量按小时」的 24 根柱。线路状态卡最后没有用 3D —— 它承载的是「每条线路的实时速率」这类需要精确读数的地方，立体化反而妨碍比较。这条差异记在这里，免得下次有人照着早先的方案去找那两处 3D。

层次深度则用在卡片与磁贴上：`--card` 对 `--background` 的明度差、1px 边框、`--shadow-sm`，以及 `#view` 的两级表面。

- 不做旋转、拖拽、缩放等交互，图表始终是静态视角。

理由：路由器管理界面常在手机与低端浏览器上打开，WebGL 上下文与包体都不划算；而主题已禁止渐变，等距三面的纯色明度阶本来就不需要渐变，反而比带光照的 WebGL 更干净。交互式 3D 还会引入指针事件与重绘开销，与看板追求的刷新节奏冲突。

## Consequences

- 等距投影的深度不能靠阴影伪造，必须是三个实际绘制的面，否则缩放后比例会失真。`tests/charts.test.js` 直接断言每根柱有三个面（`dash-iso-front` / `-side` / `-top` 各一次）。
- 带 `preserveAspectRatio` 的图形没有固有高度：容器必须显式给高度，否则会按宽度撑成正方形（真机上温度仪表曾长到 179px 而槽位只有 34px）。
- `prefers-reduced-motion` 下图形静止即可，不需要为 3D 单独做降级——它本来就不动。
