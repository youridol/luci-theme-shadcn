# 3D 视觉的边界：只做层次深度，不做等距投影、不做交互式旋转

看板要求「3D 显示」。三种读法差别很大：CSS 层次深度（透视、倾斜、分层投影）、SVG 等距伪 3D（柱体画成顶面/侧面/正面三个纯色块）、WebGL 真 3D。

决定：只做层次深度，等距投影与 WebGL 都不做。

> **修订（adr/0008）。** 本文原先还保留了一处等距投影 —— `isoBars` 画的「今日流量按小时」24 根柱。那一版的问题是柱高与实际字节数的对应关系读不出来：24 格挤在 100 单位宽的 viewBox 里，顶面还要额外占掉 `depth` 的宽度，且没有零基线参照。现在改成平面圆角柱（每格一条等高轨道 + 圆角柱体 + 峰值提亮），等距投影在主题里已完全退场。`_charts.js` 里不再有 `isoBars`，`tests/charts.test.js` 也改成了断言「每格一条轨道 + 恰好一根峰值柱」。

层次深度用在卡片、磁贴与图表本身上：

- `--card` 对 `--background` 的明度差、1px 边框、`--shadow-sm`，以及 `#view` 的两级表面；
- 图表内的层级用「轨道 / 数据 / 高亮」三级不透明度表达（柱有背景轨道，峰值柱拉满，空槽只留发丝线）。

不做旋转、拖拽、缩放等交互，图表始终是静态视角。

理由：路由器管理界面常在手机与低端浏览器上打开，WebGL 上下文与包体都不划算；主题又禁止渐变（adr/0003），带光照的真 3D 无从表达明暗。交互式 3D 还会引入指针事件与重绘开销，与看板每秒一次的刷新节奏冲突。

## Consequences

- 深度不能靠阴影伪造，也不能靠剪切面伪造。层级只能来自 token 明度阶、边框、投影与不透明度阶 —— 这三样在缩放后都不会失真。
- 带 `preserveAspectRatio` 的图形没有固有高度：容器必须显式给高度，否则会按宽度撑成正方形（真机上温度仪表曾长到 179px 而槽位只有 34px）。
- `preserveAspectRatio="none"` 的图表会把 `<circle>` 压成椭圆：端点标记因此改用「零长度线段 + 圆头 + `non-scaling-stroke`」。
- `prefers-reduced-motion` 下图形静止即可；数值补间由 `_charts.js` 的 `reduceMotion()` 直接跳过（见 adr/0008）。
