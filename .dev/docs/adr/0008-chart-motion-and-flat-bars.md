# 图表改成平面圆角柱 + 帧补间动画，等距投影退场

看板的图表原先是折线 + 等距三面柱 + 纯色扇形环，配色只有一种 `--primary` 的不同透明度，数值变化靠「每秒整块重画」。观感偏旧，且有两个实际缺陷：

1. **重画即闪烁。** 卡片内容每秒重建，任何 CSS 入场动画都会跟着每秒重放一次，所以原来干脆完全不做动画 —— 数值是「跳」到新值的，读不出变化方向。
2. **等距柱读不出量。** 24 根柱挤在 100 单位宽的 viewBox 里，每个柱面还要分掉 `depth` 的宽度；顶面被剪切后，柱高与实际字节数的对应关系只有目测，没有轨道、没有零基线参照。

决定：

- **等距投影退场**（推翻 `adr/0007` 的唯一一处 3D 用法）。小时柱改成平面圆角柱：每格一条等高的淡轨道、柱体填在轨道里、峰值柱单独提亮。轨道让「这个小时有没有数据」与「这个小时用了多少」分开表达，比三面体更容易横向比较。
- **动画放进 JS 的帧补间**，不放进 CSS。`_charts.js` 用一个 `memory` Map 记住上一次的数值（键由调用方给，例如 `card-hours`、`host:192.168.3.238`），下一次绘制时在 420 ms 内插值几何。卡片每秒重建不影响它 —— 状态不在 DOM 里。
- **首帧用一次性描边动画**（`dash-enter` + `pathLength="1"`），700 ms 后由脚本摘掉这个类。不摘的话，动画被禁用或被节流的浏览器会让线条永远停在 `stroke-dashoffset: 1`（即不可见）。
- **`prefers-reduced-motion` 直接画终值**：`animate()` 在减少动效时同步执行 `step(1)`，不排帧。

## 为什么不是「CSS transition」

柱高是 `path` 的 `d`，环是 `stroke` 的弧，都不是可过渡属性；`rect` 的 height 能过渡，但圆角、轨道、峰值高亮与 24 格等宽都要求 path 几何。用 CSS 就只能退回 `transform: scaleY()`，而 scaleY 会把圆角一起拉扁。

## 为什么记忆放在模块级 Map 而不是元素上

卡片 body 每秒 `textContent = ""` 重建，任何挂在元素上的上一帧状态都会随之丢失。键由调用方给，而不是自动分配，因为排行顺序会变 —— 用行号当键会让「第 1 名」的条从上一次的数值补间到另一个人身上，看起来像流量突增。

## Consequences

- `_charts.js` 增加约 8 KB 源码（terser 后补丁 JS 从 33 KB 涨到 44 KB），换来所有图表的平滑变化。补丁不进主包，只有概览页按需加载。
- 新 API：`lineChart` / `multiLine` / `hourBars` / `animate` / `reduceMotion` / `reset`；`isoBars` 删除，`tests/charts.test.js` 里断言「三面各一次」的用例改成「每格一条轨道 + 恰好一根峰值柱」。
- 图表颜色不再靠透明度堆叠：环形用 `stroke`（获得圆头端点），排行条用 `stroke` + `non-scaling-stroke`（4px 圆头在任何卡片宽度下都不变形），端点光点用「零长度线段 + 圆头」而不是 `<circle>` —— `preserveAspectRatio="none"` 会把圆压成椭圆，实测出现过 28×12 的扁块。
- 端口流量的上下行改成共用一套纵轴：原来两条线各自算范围，视觉上「上行和下行一样忙」，而实际上行只有下行的六分之一。共用纵轴后两条线可以直接比较，精确读数由图例给出。
- 内存环形从「空闲/已用两个扇区」改成「一条轨道 + 已用弧 + 中心读数」；`ring` 增加 `total` 选项，单个数值也能画成仪表而不是占满整圈。
