# 概览页看板

概览页（`admin/status/overview`）本该是「一眼看清当前网络状态」的地方，但 LuCI 原生把它渲染成一列 `cbi-section`，每块都是「标签 / 值」两列表格，关键数字埋在下面几屏。这个文档描述把整页改造成看板的方案：要显示什么、数据从哪来、怎么画、怎么降级。

实现落在 on-demand patch `admin-status-overview`（`src/resource/patches/admin-status-overview.js` + `src/media/patches/admin-status-overview.css`），后端在 `root/usr/share/rpcd/ucode/shadcn.uc`。相关决策见 `adr/0001` 到 `adr/0007`；补丁机制本身见 [`patches.md`](patches.md)。

## 目标

首屏回答四个问题，然后才允许用户往下滚：通不通、忙不忙、哪里有问题、谁在占带宽。任何需要点开才能知道的数字，都是没达到目标。

### 异常与诊断

**异常**是持续状态，由阈值判定，随刷新自动出现或消失，按严重度排序堆在顶部横幅区。默认判定线：

| 条件               | 阈值                                  | 状态                         |
| ------------------ | ------------------------------------- | ---------------------------- |
| conntrack 占用     | > 80%（warning）/ > 95%（danger）     | **已实现**                   |
| 可用内存           | > 90% 已用                            | **已实现**                   |
| 温度               | > 80 °C（warning）/ > 90 °C（danger） | **已实现**                   |
| 负载               | > 核心数                              | **已实现**                   |
| 多数连接无字节计数 | > 50%                                 | **已实现**（info，不是故障） |
| 丢包率             | > 5%                                  | 未实现 —— 需要延迟探测，见下 |
| DNS 解析           | > 500 ms                              | 未实现 —— 同上               |

阈值可用 `/etc/config/shadcn-dashboard` 逐项覆盖，**判定在后端**（`shadcn.uc` 的 `buildAlerts`），因为后端才握有原始数值；前端拿到的是已经四舍五入的百分比，用它去比阈值会在边界上错判。每条告警都带 `limit`，横幅里直接显示「阈值 0.1%」这类字，有覆盖时再补一句「阈值来自 /etc/config/shadcn-dashboard：…」，所以改完配置能确认生效。

配置随包安装（`root/etc/config/shadcn-dashboard`），由 opkg 按 conffile 处理，升级时保留你的修改、把新版本写成 `.opkg-dist` 放旁边。它同时也是**可选**的：文件不存在时全部落回默认值，看板照常工作，设置页会给出「Create configuration」按钮把它重建出来。

改它请走 **System → Dashboard Alerts**，不要手写 —— 页面会校验取值范围，并把每项的内置默认值显示成 placeholder。

非数字或负数的项会被忽略并回退默认值 —— 一个打错字不该把阈值变成 0 而满屏报警。**这里不能用 `isNaN`**：ucode 没有它（`isNaN('5')` 抛 "left-hand side is not a function"），而读取处的 `try/catch` 会把这个错误吞掉并回退默认值，表现为「配置写了但永远不生效」且毫无提示 —— 真机上就是这样静默失效的。改用 `n != n` 判 NaN。

真机验证：写 `conntrack_warn=0.1` 后横幅立刻出现 `danger · 连接表接近上限 · 843 / 131072（0.6%）· 阈值 0.1%`；删掉文件后阈值回到 `80/95`、`source: default`。

**丢包率与延迟为什么还没做**：它们不是读一个文件就能得到的量，需要周期性发探测包（ICMP 或 UDP）并统计。这与「快路径只读常量级文件」的纪律冲突 —— 探测本身会产生网络流量，且需要一个额外的守护进程或后台定时器。设计意图是把它放进「诊断」这条**按需**路径而不是常驻采集，所以它属于下面「一键诊断」的一部分，不在告警阈值里。

**一键诊断**：一次性检查，由 `诊断` 按钮触发，后端 `shadcn.diagnose` 依次测：到默认网关 ping、到公网 ping、DNS 解析耗时。结果按通过 / 警告 / 失败三档逐项显示，并给出「X 项未通过」这类一句话结论与「N ms 执行」的时间戳。诊断结束即结束，不参与后续刷新。

三项的**探针选择本身就是设计**，都来自实测而非默认值：

| 项     | 探针                                                                        | 为什么                                                                                                                         |
| ------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 到网关 | `/proc/net/route` 里目标为 `00000000` 的那行的网关（小端序十六进制解出 IP） | 不解析 `ip route` 的文本；这台设备实测解出 `100.119.0.1`，与 `ip route` 一致                                                   |
| 到公网 | **`223.5.5.5`**（阿里公共 DNS）                                             | 这台线路对 `8.8.8.8` 是 **100% 丢包**、对 `223.5.5.5` 是 21.8 ms。用 8.8.8.8 会把「屏蔽 Google DNS」报成「公网不通」，那是误诊 |
| DNS    | `nslookup www.baidu.com`，只取 `Non-authoritative answer:` 之后的 `Address` | 前面那段 `Address: <server>:53` 是本机用的 DNS 服务器，不是解析结果                                                            |

单包 ping（`-c 1 -W 2`）而不是 3 个包：100% 丢包时每包要等满 `-W`，3 个包实测 **6016 ms**，直接超预算；改单包后整轮 **38 ms**。

真机结论：`ok: true`、`全部通过`、网关 1.5 ms / 公网 21.8 ms / DNS 9 ms → `183.2.172.177`。按钮在请求期间变「诊断中…」并禁用，完成后恢复；结果面板可关闭。

### 告警的真机验证

三档不是照着代码推断的，是调低 `/proc/sys/net/netfilter/nf_conntrack_max` 造出真实占用后测出来的：

| 占用       | 结果                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------- |
| 81.1%      | `warning`「连接表接近上限 951 / 1172（81.1%）」                                                      |
| 96.5%      | `danger`「连接表接近上限 919 / 952（96.5%）」，左边框 `oklch(0.704 0.191 22.216)` 即 `--destructive` |
| 恢复上限后 | 告警自动消失，只剩 `info` 那条                                                                       |

排序也验证过：`warning` / `danger` 排在 `info` 之前。**告警是持续状态**这一点因此成立——它随数据自动出现和消失，而不是一次性事件。

验证过程中踩到一个值得写下来的坑：重启 `rpcd` 会让浏览器会话失效，此时**所有** rpcd 调用（包括 `session/get`）都返回 `-32002 Access denied`，看起来像 ACL 配错了。排查时要先区分「ACL 没授权」和「会话过期」——前者去查 `/usr/share/rpcd/acl.d/*.json` 与会话里 `acls.access-group` 的组名，后者重新登录即可。本次实测确认 ACL 是正确的：会话里明确授予了 `"shadcn": ["connections", "resolve", "dashboard"]`。

## 数据通路

### 快慢分离

默认 **5 秒**刷新。若每次都做连接表全表解析，ARM 设备上单核占用会稳定在几个百分点。因此拆成两条：

|                    | 快路径                                                                    | 慢路径                 |
| ------------------ | ------------------------------------------------------------------------- | ---------------------- |
| 默认间隔           | 5 s（可选 1/2/5/10/30/60）                                                | 60 s                   |
| 读取               | `/proc/net/dev`、`/proc/loadavg`、`/proc/meminfo`、`/sys/class/thermal/*` | 连接表、排行聚合、回看 |
| 成本（后端）       | 常量级，**10 ms**                                                         | **630 ms**             |
| 成本（浏览器往返） | **约 1 s**                                                                | 1.2–1.5 s              |

两者是**同一个** rpcd 方法的不同 `sections`，不新开对象。

**为什么默认不是 1 秒。** 真机实测（LEDE 24.10.5 / x86_64）：同一个调用在本机 `ubus call` 只要 10 ms，走 ucode 直连 ubus socket 也是 10 ms，但从浏览器发起要 **716–1202 ms**（连续 5 次，中位 1012）。连 LuCI 自己的 `system.board` 都要 469–1002 ms，所以这约 1 秒是 **rpcd/uhttpd 的 HTTP 层固定开销**，与采集器无关 —— 换更快的后端也没用。1 秒仍保留在预设里（局域网有线条件下有意义），但默认值不该把它当常态。

降速判定因此改成**相对**阈值（当前间隔的 2 倍，且不低于 1500 ms），而不是绝对毫秒数：早先写的 400 ms 在往返本来就有 1 秒的机器上每次都触发，看板一打开就显示「已降速」，而实际并没有变慢。

### RPC 形状

现有 `shadcn` 对象已有 `connections { ip, limit }` 与 `resolve { ips }`，抽屉继续用它们，一字不改。看板新增：

```
shadcn.dashboard { sections: String }
    sections: "fast" | "slow" | "all"，逗号分隔可多选
    返回: {
      available: bool,
      at: 采样时刻,
      fast: { … },
      slow: { … },
      caps: { temperature: {available, reason, sensors}, conntrack: bool,
              cpus: n, ports: [name, …] },
      degraded: { … }
    }
```

`caps` 回报本次探测到的能力，前端据此决定画哪些卡，而不是自己猜。`sections` 用逗号分隔的字符串而非数组 —— 与 `resolve` 的 `ips` 同理，`String` 在各版本 rpcd 上都可靠。ACL 只加读权限，`root/usr/share/rpcd/acl.d/shadcn.json` 的 `ubus.shadcn` 列表加进 `dashboard`。

**`caps.cpus` 不是可有可无的字段。** 负载告警的判据是「1 分钟负载 > 核数」，而前端拿不到 `/proc/stat` 的核数；缺了它，条件恒为假，那条告警**永远不触发且不报错**——真机上就是这样静默失效的。同理 `ports` 是前端挑选 WAN 接口的唯一依据。

前端的刷新节奏：快路径按用户选定的间隔（预设 **1 / 2 / 5 / 10 / 30 / 60 秒，默认 5**，另有暂停与手动刷新），慢路径固定 60 秒。页面隐藏即停（与路由已有的 `visibilitychange` 纪律一致），恢复可见时立刻补一轮。降速判定用**相对阈值**：一次快路径超过「当前间隔的 2 倍且不低于 1500 ms」时放宽一档，并在状态行标注「已降速（采集耗时过长）」。

### 能力探测

判定基准只能是「有没有这个文件 / 这个 ubus 对象 / 这个命令」，不按设备型号分支 —— CI 目标设备是 x86/64，而性能基线来自 Cudy TR3000 的 ARMv8。

- **温度**：先 `/sys/class/thermal/thermal_zone*/temp`，无则 `/sys/class/hwmon/hwmon*/temp*_input`（取 `name` 含 `coretemp` / `k10temp` / `cpu_thermal` 的），再无则「不可用 · 无温度传感器」。
- **线路**：`netifd` 的 WAN 逻辑接口优先；装了 `mwan3` 则逐条线路；都没有则退化为「有默认路由的接口」。
- **无线 / cellular / `nlbwmon` / `vnstat` / `sqm`**：存在与否只影响对应卡片是否出现。

`Makefile` 的 `LUCI_DEPENDS` 保持只有 `luci-base`，外部包一律运行时探测。

### 回看与采样器

见 `adr/0005`。要点：procd 启动的后台采样器（`root/` 下按 luci.mk 约定原样装进设备根），固定 1 分钟粒度、只留 24 小时、写 tmpfs 环形文件。`vnstat` / `nlbwmon` 存在时优先用它们的历史，没有才退回自研回看，两者都缺时如实显示「无历史」。重启后回看清零，界面要能表达「回看自 <时间> 起」。

已落地：`root/usr/share/ucode/shadcn/sampler.uc` + `root/etc/init.d/shadcn-dashboard`（procd，respawn 3600/5/5，nice 19）。真机验证：70 秒内点数 3 → 4，`step=60`，环形截断 1450 → 1440，损坏 JSON 回落到空骨架。

**这台设备的探测结果**：`vnstat` 未安装；`nlbwmon` 已装但**没有 ubus 对象**，其数据库是私有二进制格式（`/var/lib/nlbwmon/YYYYMMDD.db.gz`）。因此当前实现只用自研 conntrack 聚合做排行，不解析 nlbwmon 的库 —— 那需要逆向它的格式，是另一个量级的决定。`caps` 现返回 `temperature` / `conntrack` / `cpus` / `ports` 四项，暂无外部包字段；将来接入时增补即可，不影响既有消费方。

## 视觉约束

- **只有暗色**（`adr/0002`）。`light` 派生与三态切换全部移除。
- **禁止渐变**（`adr/0003`）。深度用 token 明度阶、1px 边框、投影表达。构建产物里出现任一 gradient 函数即失败 —— 这项检查要加进 `scripts/check-built-css.js`，目前该脚本只查 `color-mix()` 与相对 `oklch()`。
- **图表全手写 SVG**（`adr/0004`）。零 canvas、零 WebGL、零第三方图表库。
- **图标内联 + `currentColor`**（`adr/0006`）。删除 `_shared.css` 的 `filter` 反色。
- **等距投影只用一处**（`adr/0007`）：今日流量的小时柱。线路卡没上 3D —— 那里需要精确读数，立体化妨碍比较。层次深度（token 明度阶 + 边框 + 投影）用在卡片与磁贴上。等距三面必须是实际绘制的三个面，不靠阴影伪造。

CSS 前缀统一 `shadcn-dash-`。旧的 `.shadcn-metrics` / `.shadcn-metric` 与它们的磁贴带退役，由新看板的概况带取代。

## 布局与移动端

单页纵向滚动，顶部吸顶分区导航（概况 / 线路 / 资源 / 流量）。

- ≥ 1280 px：四列网格
- 768–1279 px：两列
- < 768 px：单列，且把 C 组资源类与 D 组排行**折叠成可展开区块**，只保留 A 概况带与异常横幅常驻。手机上真正需要的是「现在通不通、哪里出问题」，排行与历史可以等展开。

## 降级呈现

三段，缺一不可：

1. **无 JS**：原生概览区块照常显示。隐藏动作只在脚本确实接管成功之后执行 —— 这条保证脚本未运行或被拦截时整个概览页仍然可用。
2. **RPC 失败**：保留上一帧画面，顶部出现「数据已过期 N 秒」并标红。不闪空，不把错误画成 0。
3. **单个指标不可用**：卡片显示「不可用 · 具体原因」（无传感器 / 无外部包 / 权限不足），卡片不消失、位置不跳动。

## 与在线主机抽屉的关系

抽屉（点主机名看逐条连接，13 列，1 s 轮询）保留，后端接口不动，只把入口迁到看板的「Top 主机」排行行与「在线终端」磁贴的展开列表 —— 从看板下钻到某台主机的实时连接是最常用的运维路径，不能丢。原生「在线主机」表随原生区块一起进入逃生口。

### 设置页

`admin/system/dashboard-alerts`，源码 `src/resource/view/shadcn-dashboard.js`，菜单由 `root/usr/share/luci/menu.d/luci-theme-shadcn.json` 注册，ACL 在 `acl.d/shadcn.json` 里加了 `uci.shadcn-dashboard` 的读与写。

每个字段把内置默认值显示成 placeholder，留空即删除该项 option。**「没有 option」不等于 0，而是「用默认值」** —— 这一点很关键：升级后默认值变了，没配过的人应当跟着变。所以页面从不写入用户没输入的值。

三个坑，都是真机上撞出来的：

1. **`uci.load()` 在配置不存在时 reject**，`view.js` 把 rejected load 当成「页面永远没就绪」，界面就卡在「正在载入视图…」。必须 catch。
2. **只 catch load 还不够**：`form.Map#render()` 自己也调 `uci/get`，同样抛错。所以 `render` 要按 `load` 的结果分支，缺文件时走 `renderMissing()`。
3. **UCI 没法创建不存在的配置文件**：`ubus call uci add` 返回 Not found，`uci set` 也是 `uci: Entry not found`。设置页自己造不出这个文件，于是后端加了 `shadcn.createConfig`（rpcd 进程能直接写 `/etc/config`），页面上给一个「Create configuration」按钮，建完重载。

`createConfig` 只写默认值，已存在则不动（返回 `created: false`），避免覆盖用户编辑。

真机验证：表单改 `conntrack_warn` → 保存并应用 → `uci show` 得 `'1'`、后端 `thresholds` 得 `value 1 / source config`；删掉文件 → 页面给出说明与按钮 → 点击后文件重建（600 权限，与 `/etc/config/system` 一致）、表单恢复 6 个字段。

### `#view` 网格（已清理）

原来 `#view` 在 ≥1024px 是两列（`1.15fr 1fr`），那是给原生区块并排用的。看板接管后原生区块已隐藏，但网格还在，看板只能靠 `grid-column: 1/-1` 跨列抵消回来 —— 宽度是「修正出来的」而不是本来如此。

现在 `#view[data-dashboard="on"]` 收敛为单列，看板自然铺满（实测 `boardW === viewW === 1276`）。**逃生口必须同时保留两列**：`data-show-native="true"` 时原生区块回来，网格也要回来，所以那条单列规则带了 `:not(:has(> .shadcn-dash[data-show-native="true"]))`。实测三态：看板 1276 单列 → 原生 674+586 两列且 6 个区块可见 → 返回看板 1276 单列。

## 已知的坑

- **`#view` 是异步渲染的**：脚本求值时它可能还不存在。沿用现有的观察器 + 兜底定时器；写 DOM 会让观察器自激，必须设闩。
- **LuCI 每 5 秒重写整行**：任何插进原生表格的元素都会被抹掉。抽屉用的「打属性 + 事件委托」方案是为此而来，看板接管后原生表进逃生口，这个问题随之消失。
- **`ucode` 没有函数提升**：前向调用会在运行时抛错，且调用方会吞掉。相关函数必须按依赖顺序声明。
- **`match()` 返回数组或 `null`，不是布尔**：赋给布尔变量前显式和 `null` 比较。
- **rpcd `args` 必须写 `String` 字面量**：写成小写变量名签名看着对，实际会丢掉参数，`req.args` 永远为空。
- **ucode 的整数除法向零截断**（本轮踩了三次）：`count / max` 在 `count < max` 时得 0，`dIdle / dTotal` 在增量小时得 0，`round(34.4) / 10` 得 3 而不是 3.4。凡是要小数的地方，除法两侧都显式 `+ 0.0`。这个错误**不报错、不崩溃，只是恒为 0**，靠读代码看不出来。
- **ucode 没有 `Math`，字符串也没有 JS 的原型方法**：数学函数在 `math` 模块（`import { round } from 'math'`），大小写转换用 `uc()` / `lc()`。`Math.floor` 与 `str.toUpperCase()` 都会抛「access to undeclared variable」/「not a function」，而调用方会吞掉。
- **`ucode -c file.uc` 会把 `export` 报成语法错误**：模块文件要在被 `require()` 时才合法，`-c` 只适合单文件脚本。验证模块的正确方式是真的 `import` 它并调用。
- **`uloop` 模块不保证存在**：这台设备的 ucode 构建 import 它时报 `Unable to resolve path for module 'uloop'`，所以采样器的等待用 `system('sleep N')`。代价是每分钟 fork 一个 `/bin/sh`，只适用于 60 秒这种粒度。
- **重启 `rpcd` 会让浏览器会话失效**：此后所有 rpcd 调用（含 `session/get`）都返回 `-32002 Access denied`，很容易误判成 ACL 配错。先去查会话授权（`session login` 的返回里直接带 `acls.access-group`），确认无误就重新登录。
- **带 `preserveAspectRatio` 的 SVG 没有固有高度**：只给 `width: 100%` 会让它按容器宽度撑成正方形（温度仪表真机上曾长到 179px 而槽位只有 34px）。容器必须显式给高度。
- **ucode 不支持 `for...of`**：`for (const c of arr)` 是**语法错误**，整个模块在加载期就失败。而 rpcd 只表现为「`ubus list` 里没有这个对象」，看起来像装错了或 ACL 有问题。用 `for (x in arr)`。
- **`arr.filter(fn)` 这种数组方法也不可用**：ucode 的 `filter` 是全局函数，写成 `filter(arr, fn)`。
- **ucode 正则不支持 `[\s\S]` 这类组合**：`match(text, /A:([\s\S]*)/)` 会静默匹配失败，于是「DNS 永远未通过」。要截取一段就 `split(text, 'A:')[1]`。
- **`_` 前缀的补丁片段不会进产物**：`_charts.js` 靠 `//#include ./_charts.js` 在构建期内联，目标缺失时构建直接失败（否则会发出一个一加载就抛错的补丁）。
- **补丁注册键必须等于文件名 stem**：路由按 `window.luciPatches[stem]` 查找，键写错的话 `unmount()` 永远不被调用，监听器会越过页面存活。
- **ucode 没有 `isNaN`**：`isNaN('5')` 抛 "left-hand side is not a function"。若外面包着 `try/catch`，错误被吞掉并回退默认值，表现是「配置永远不生效」且没有任何提示。判 NaN 用 `n != n`。
- **`round(x)` 返回 int**：`round(0.55 * 10) / 10` 得 0（int/int 又走整数除法）。要小数必须 `round(x, true)`。这已经是整数除法在本项目里第四次咬人（CPU 使用率、conntrack/mem/storage 百分比、这里）。
- **ucode 不接受多行函数调用的尾随逗号**：`f(\n a,\n b,\n )` 报 `Expecting expression`，报错位置指向 `);`，看起来像别的问题。写成一行。
- **LuCI 的 `uci.load()` 对不存在的配置会 reject**，而 `view.js` 把 rejected load 当成「永不就绪」，页面卡在「正在载入视图…」。`form.Map#render()` 也会因为同样的 `uci/get` 失败而抛错 —— 两处都要处理，只 catch 一处不够。
- **UCI 造不出不存在的配置文件**：`ubus call uci add` 与 `uci set` 都返回 Not found。要创建只能由有文件写权限的进程来（本项目用 rpcd 里的 `createConfig` 直接写 `/etc/config`）。
- **`rpc.declare()` 返回的是可直接调用的函数**，别写 `.call()` —— 那是 `Function.prototype.call`，会把第一个参数当 `this` 并丢掉真正的参数。
- **`depends.uci` 会把整条菜单藏起来**：菜单项写了 `"uci": { "shadcn-dashboard": true }` 而配置文件不存在时，菜单直接不出现，页面 404，看起来像没装上。配置本身是可选的，就别把它写成菜单的前提。
